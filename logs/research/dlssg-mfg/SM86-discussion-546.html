I can reproduce the Zenless Zone Zero crash on an RTX 3090 (SM86) using both the 310.1 and 310.9.1 builds. I did some Level 3 logging to narrow down where it fails.

System / game

  • Game: Zenless Zone Zero 3.2
  • GPU: NVIDIA GeForce RTX 3090 (SM86)
  • NVIDIA driver: 616.92
  • Windows build: 26200
  • HAGS: Enabled
  • API: D3D12
  • Streamline interposer: 2.11.1.0
  • Current tested runtime: 310.9.1
  • Proxy: version.dll only
  • Optimized=0
  • MaxGeneratedFrames=3
  • Logging Level=3
  • Runtime Mode=Bundled

The mod appears to initialize correctly. The log reports:

  • Physical GPU correctly detected as SM86
  • router:"sm86"
  • image:"cubin_sm86"
  • route_active:true
  • Architecture spoof is successfully applied to sl.interposer.dll
  • HAGS detected as enabled
  • NGX hooks attach successfully
  • FrameGeneration.Available=1
  • FrameGeneration.NeedsUpdatedDriver=0
  • FrameGeneration.FeatureInitResult=1
  • DLSSG.MultiFrameCountMax=3
  • NVSDK_NGX_D3D12_CreateFeature returns success

However, immediately before the successful CreateFeature call, Level 3 logging shows the following:

kernel_create
actual_sm: 86
feature: 1
image: original
routed: false
shader: 0x0
source_rva: 0x7a9a0000
status: -14
thunk: create_with_name

kernel_create
actual_sm: 86
feature: 1
image: original
routed: false
shader: 0x0
source_rva: 0x7a9a0000
status: -14
thunk: create_ex

kernel_create
actual_sm: 86
feature: 1
image: original
routed: false
shader: 0x0
source_rva: 0x7a9a0000
status: -14
thunk: cu_module

cu_chain_launch
entries: 0
rewritten: false
status: -14

After that, NGX capability reporting still succeeds:

FrameGeneration.Available = 1
FrameGeneration.NeedsUpdatedDriver = 0
FrameGeneration.FeatureInitResult = 1
DLSSG.MultiFrameCountMax = 3

and CreateFeature reports:

feature_id: 1
status: 0x1
succeeded: true

The game then crashes during its configuration/loading stage. There are no Evaluate events after this.

I also reproduced the same general failure with the 310.1 runtime. On 310.1 the failing kernel was at a different runtime RVA (0x8fc70000 / similar depending on the run), but it likewise produced:

kernel_create
image: original
routed: false
shader: 0x0
status: -14

and the game crashed before reaching an Evaluate.

I tested 310.9.1 again with all optimization features disabled (Optimized=0), so the current reproduction is using stock tier 0:

optimized_kernels: false
image_patches: false
image_approx: false
optimized_tier: 0
optimized_tier_name: stock

The result is unchanged.

For comparison, using the mod with a configuration that does not reach this DLSS-G initialization path allows ZZZ to launch normally, so the crash appears specifically associated with DLSS-G initialization/kernel routing rather than general game startup.

It looks like the capability/architecture side is succeeding on the RTX 3090, but this particular kernel is not being routed/replaced (routed:false, shader:0x0, status:-14) before CreateFeature completes.

Is this an unsupported/missing kernel signature in ZZZ's current DLSS-G implementation, or is there another diagnostic/compatibility option you would like me to test?

I can provide the complete Level 3 loader/backend JSONL logs from both 310.1 and 310.9.1 if useful.
