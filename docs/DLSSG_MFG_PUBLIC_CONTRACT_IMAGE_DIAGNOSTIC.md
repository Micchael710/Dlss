## Public contracts

Each public helper invocation binds OutputInterpolated and OutputDisableInterpolation and sets count/index. Therefore PER_INDEX_OR_GROUP=NOT_DOCUMENTED_IN_INSPECTED_PUBLIC_HEADERS; semantics confidence is high for optional pointer and insufficient for write scope. No index-specific exception or flag substitution is justified.

[NVIDIA evaluation definitions](https://raw.githubusercontent.com/NVIDIA/DLSS/main/include/nvsdk_ngx_defs_dlssg.h) describe count as number of generated frames and index as the requested output position. Our host invokes the public helper for each distinct output of one real pair, using persistent NGX handles and imported GPU resources.

The same definitions specify a disable resource of at least four bytes and a boolean true in the first byte when interpolation must be suppressed. Its wording covers interpolated frame(s) of the current frame. This suggests a group-level intent, but does not specify which indexed Evaluate writes the hint, nor establish that another index's zero authorizes an untouched resource. We observed entire words 0, 1 and 0xffffffff; the latter also has first byte 0xff. Reading only the first byte would therefore not solve this run's ambiguity. No group-validity substitution was implemented.

## Architectural comparison

[OptiScaler DLSSG_Dx12.cpp](https://raw.githubusercontent.com/optiscaler/OptiScaler/master/OptiScaler/framegen/dlssg/DLSSG_Dx12.cpp) creates a Streamline-interposed DXGI swapchain, reads `numFramesToGenerateMax` and clamps the configured interpolation count to that capability. Dispatch assigns `DLSSGOptions.numFramesToGenerate` and calls SetOptions. The [public INI](https://raw.githubusercontent.com/optiscaler/OptiScaler/master/OptiScaler.ini) maps counts 2/3/4 to x3/x4/x5. A selectable multiplier is not evidence that every GPU/backend actually produces that many valid outputs.

[OptiScaler Client](https://raw.githubusercontent.com/Optiscaler-Client/Optiscaler-Client/main/README.md) installs/configures components and exposes multipliers with path/nvngx/Streamline setup. It is a configuration/distribution layer, not an independent generation contract. [DLSS Enabler's repository](https://github.com/artur-graniszewski/DLSS-Enabler) packages OptiScaler and describes compatibility/simulation paths. Those labels alone do not prove native NVIDIA MFG on this host; the actual selected backend and outputs still require validation.

[Streamline's DLSS-G guide](https://raw.githubusercontent.com/NVIDIA-RTX/Streamline/main/docs/ProgrammingGuideDLSS_G.md), section 6.2, exposes numFramesToGenerate and a queried maximum, dependent on hardware/system. It presents multiple frames per application Present. Resources are consumed during swapchain Present, and pacing is managed internally. The inspected public route does not provide an output-texture export contract that we can substitute directly into our sidecar leases. Coexistence with Vulkan/D3D12 sharing and a sole PresentWorker owner is unproven. Implementing this route would require a presentation architecture audit rather than simply replacing a count setter.

Our current route directly calls public NGX in a D3D12 sidecar and returns GPU-owned Vulkan images to the existing PresentWorker, with zero provider Present calls. Its external component configuration currently sets MaxGeneratedFrames=2. Hence the measured getter=2 is a configured ceiling, not proof that the architecture intrinsically caps MFG at 2. The [component's public installation guide](https://raw.githubusercontent.com/sdli1995/dlssg_for_sm86/main/docs/INSTALL.en.md) documents MaxGeneratedFrames and distinct runtime ceilings; current documentation cannot alone certify the pinned installed component at a higher count. Higher capability queries/runs remain gated on x3 PASS. Getter forcing, plugin memory patches and proprietary binary changes are excluded.
